# 量化回测中的偏误全景

> "当你用今天的最高价作为买入信号，假设自己能在那个瞬间成交——你就在骗自己。"
> 所有回测偏误的本质，都是**信息的时间错位**：用未来才可知的信息，假装过去就做了决策。

---

## 一、价格类前视偏误（你提到的核心问题）

### 1.1 当日价格数据的"时间箭头"

当我们拿到 yfinance 返回的日线数据：

```
date       open   high   low    close  volume
2026-07-22 100    105    99     103    500000
```

**看起来**——7月22日开盘100、最高105、最低99、收盘103、成交50万股。
**但实际上**——如果你是策略在22日盘中运行：

| 数据 | 实际可知时间 | 回测中误用的后果 |
|:-----|:------------|:----------------|
| Open | 开盘后（9:30）即知 | 通常没问题 |
| **High** | **收盘前最后一刻才确认** | **用High做止盈/突破信号→虚高胜率** |
| **Low** | **收盘前最后一刻才确认** | **用Low做止损/抄底信号→虚低回撤** |
| **Close** | **收盘后（15:00/16:00）** | **用Close做信号→当日不能成交** |
| **Volume** | **收盘后** | **用Volume做信号→当日不能成交** |
| Adj Close | **数日后（等公司行动调整）** | **包含了未来拆分/分红信息** |

**典型错误示例：**

```
❌ 错误策略："当日收盘价突破20日均线买入"
   回测：用当日Close做信号 → 假设Close出来的瞬间就成交了
   现实：Close出来已经是收盘后，最早次日开盘才能成交
   差异：次日开盘=Close×(1+隔夜跳空)，跳空可能吃掉突破信号的全部利润

❌ 错误策略："当日最低价跌破布林带下轨买入"
   回测：在最低价成交
   现实：最低价只有在收盘后才知道，你不可能在那一刻成交
   差异：你实际买入价可能比最低价高1-3%

✅ 正确写法："次日开盘价突破20日均线买入"
   回测：用收盘价算均线→看是否突破→次日开盘价成交
   这样才是时间顺序正确的
```

### 1.2 "日内不可知"的具体影响

**影响最大的因子类型：**

| 因子 | 误用的方式 | 效果虚高程度 |
|:-----|:----------|:------------|
| 日内反转 | 当日涨→当日卖 | ⭐⭐⭐⭐⭐ 完全伪造 |
| 上下影线 | 用High-Low区间做信号 | ⭐⭐⭐⭐⭐ 完全伪造 |
| 突破策略 | 当日突破当日追 | ⭐⭐⭐⭐ 严重虚高 |
| VWAP偏离 | 用当日VWAP | ⭐⭐⭐⭐ |
| 止损测试 | 用Low触及止损线 | ⭐⭐⭐ |
| 盘中成交量 | 用Volume判断动量 | ⭐⭐⭐ |

**正确的信号-成交时间映射：**

```
信号基准           → 信号可知时刻     → 最早成交时刻
──────────────────────────────────────────
T日开盘价          → T日9:30         → T日9:30（开盘瞬间）
T-1日收盘价        → T日0:00之后     → T日9:30（次日开盘）
T-1日全部数据      → T日0:00之后     → T日9:30
T日最高/最低/收盘/量 → T日收盘后     → T+1日9:30
T周/月数据         → T+1周/月起始    → 下一个交易日
```

## 二、财务数据前视偏误

### 2.1 财报披露时间差

A股：季报在季度结束后**1个月内**公告，年报在**4个月内**
港股：中期报告2个月内，年报4个月内
美股：10-Q（季报）在季度结束后**45天**内，10-K（年报）**90天**内

**错误用法：**
```
回测中用2026Q1的净利润做2026-02-01的选股信号
→ 实际上Q1结束是3月31日，披露是4月中下旬
→ 2月1日你根本看不到这个数据
```

**正确的做法：** 在回测中对财务数据做**至少1个quarter的滞后对齐**。

### 2.2 复权数据的陷阱

yfinance 的 Adjusted Close 是**前复权**的——它把未来的分红、拆股、配股等因素倒推回去调整历史价格。

**这意味着：**
- 用Adj Close做历史回测→价格是正确的总回报视角
- 但是Adj Close本身包含了**未来信息**
- 如果你用Adj Close做信号生成（如均线、MACD）→当日的Adj Close在当日收盘时还不可知，因为它要等公司行动发生后才调整

**修正：** 信号生成用未复权的Close，业绩计算用Adj Close。

### 2.3 "已实现"数据的幻觉

很多因子看起来"可计算"，实际上用了未来信息：

| 数据 | 看起来 | 实际发布时间 |
|:-----|:-------|:------------|
| 市盈率PE(TTM) | 随时可算 | 最后一份季报出齐后才准 |
| ROE(TTM) | 看似是过去12个月 | 最新季度的净利润滞后45-90天 |
| 股息率 | 似乎简单 | 除息日才确定，预告可能调整 |

## 三、另类数据的前视偏误（你提到的 Google Trends）

### 3.1 谷歌趋势的"今日指数"

你在回测中可能想用 Google Trends 做情绪指标：
- "2026-07-22 的 GOOGL 搜索热度"

但 Google Trends 的数据是**按天聚合**的，**当天结束前**你是拿不到完整数据的。

更关键的是——Google Trends 本身有**1-2天的处理延迟**。即使你时间戳写着"2026-07-22"，Google也可能在7月24日才最终确定这个数值。

**示例时间线：**

```
7月22日盘中：你看到Google Trends显示"今日上涨"
                → 但这是7月21日的数据！
7月22日收盘后2小时：Google更新"今日"数据
                → 但你无法在22日使用了
7月23日开盘：你终于能使用7月22日的Trends数据
                → 信号滞后了1天
```

### 3.2 其他另类数据的延迟

| 数据源 | 表面时间 | 实际可用时间 | 滞后 |
|:-------|:--------|:------------|:----|
| Google Trends | 今日 | 次日凌晨 | 1天 |
| 新闻分析 | 今日 | 实时，但NLP处理需时间 | 小时级 |
| 社交媒体情绪 | 实时 | 聚合清理需1-2小时 | ~2小时 |
| 卫星影像 | 当日 | 处理+分析需1-3天 | 1-3天 |
| 信用卡流水 | 当日 | 聚合+脱敏上报需数周 | 周-月级 |

### 3.3 规则：另类数据一律滞后1期

在回测中使用任何另类数据，**信号的可用时间 = 数据的时间戳 + 1天**。

## 四、幸存者偏差（Survivorship Bias）

### 4.1 我们现在的问题

数据库只包含 **当前** 指数成分股。历史上被剔除、退市、破产的股票全部缺失。

**示例：**

| 市场 | 当前成分股数 | 历史上曾为成分股的股票数 | 差距 |
|:-----|:-----------|:-----------------------|:----|
| US SP500 | 503 | ~1,300+（自1957年以来） | 约800只 |
| CN CSI300 | 300 | ~700+（自2005年以来） | 约400只 |
| JP Nikkei225 | 225 | ~400+（自1950年以来） | 约175只 |
| HK HSI | 85 | ~150+（自1969年以来） | 约65只 |

**影响：** 所有基于"选股"的回测都会系统性高估收益。因为表现最差的股票（被指数踢出去的股票）不在回测范围内。

### 4.2 退市偏差（Delisting Bias）

退市偏差是幸存者偏差的"极端版本"——退市股票的最后交易日往往伴随着-80%到-100%的暴跌，这些数据一旦缺失：

- 回测最大回撤被低估
- 尾部风险被低估
- 小盘价值/微盘策略的收益被高估（这类策略最容易持有退市股）

**修正建议：**
- 对US市场补充CRSP退市数据库或OTC markets数据
- 对A股市场记录退市整理期的数据
- 在回测中对小盘股做退市损失准备金：年化-0.5%到-2%

### 4.3 指数调仓偏差（Index Change Bias）

指数调仓时加入的股票往往**已经涨了很多**（价格动量效应），被踢出去的股票往往**已经跌了很多**。

如果回测使用"当前"成分股：

```
你是2005年回测
→ 你看到贵州茅台在沪深300里，假设2005年就能买
→ 但实际上茅台2005年不在沪深300里！它2006年才被加入，那时候已经涨了2倍
→ 你虚增了2倍的收益
```

## 五、前视偏误综合——检查清单

### 5.1 回测设计检查清单

每次回测前，逐项确认：

| # | 检查项 | 常见违规 | 通过条件 |
|:-:|:-------|:---------|:---------|
| 1 | 信号是否只用T-1日及以前的数据？ | 用了T日Close/High/Low/Volume | 全部信号基于T-1日收盘时已知信息 |
| 2 | 成交价是否滞后信号1期？ | Close信号→Close当日成交 | 信号发出后，最早T+1日开盘成交 |
| 3 | 财务数据是否滞后至少1季度？ | 使用了当季未出财报的TTM数据 | 所有财务数据有明确的发布日期标签 |
| 4 | 复权数据仅用于业绩计算？ | 用Adj Close做信号 | 信号用Unadj Close，业绩算Adj Close |
| 5 | 另类数据滞后至少1期？ | Trends/搜索指数当日可用 | 数据时间戳+1期 |
| 6 | 是否包括被剔除的成分股？ | 只用当前成分股做历史回测 | 有时间维度的成分股映射表 |
| 7 | 是否考虑了退市股票？ | 退市股票数据缺失 | 至少对大市场补充退市数据 |
| 8 | 指数调仓是否对齐了生效日？ | 假设成分股一直固定 | 成分股列表以公告/生效日为基准 |

### 5.2 FengInvest 系统中的具体影响

**L2b量化因子：**
- 因子计算用Adj Close → **需要改为Unadj Close**
- 信号发出→成交间隔 = 0（当日成交）→ **改为+1日**
- 财务因子直接用最新TTM → **应滞后1季**

**L1纪律规则：**
- 年线/均线用Close算 → **用Unadj Close**
- 如果规则盘中触发→触发次日开盘才可操作

**P层仓位管理：**
- 再平衡信号假设当天能完成 → **至少T+1日**

## 六、确认偏误和数据挖掘偏误

### 6.1 确认偏误（Confirmation Bias）

在FengInvest系统中：

```
提问："这个股是不是好生意？"
→ 你（或Agent）倾向于搜索支持"好生意"的证据
→ 忽略或轻化了反面证据
```

**在七层框架中的体现：**

| 层 | 确认偏误风险 | 缓解手段 |
|:---|:-----------|:---------|
| L0能力圈 | "我之前就懂这个行业"→高估理解 | 三问必须各有来源 |
| M市场数据 | 挑选支持自己观点的宏观数据 | 必须有搜索环节，禁止凭记忆 |
| L1纪律 | 对持仓股放宽纪律标准 | 规则是机器执行，不经过AI |
| L2a定性 | 大师视角确认→强化原有判断 | 用investment-team的对抗视角 |
| L3碰撞 | 碰撞变成"找理由支持买入" | 反方检查4问是硬性门槛 |

### 6.2 数据挖掘偏误（Data Mining / Overfitting）

在大量因子中挖掘后发现的"规律"几乎一定是过拟合的。

**你在FengInvest中可能遇到了：**
- 对同一数据跑了50种因子→找到3个"信号显著的"
- 但它们在新数据上大概率回归均值

**缓解：** 每个因子的有效性必须在独立样本外验证，且解释逻辑必须独立于数据。

### 6.3 选择性报告偏误

"这个月沪深300跌了3%，我们的信号没触发，很好。
上个月跌了5%我们也没触发… 嗯上个月不讲。
年初至今跑输基准2%… 这个不说也行。"

**唯一解法：** 记录所有信号和决策，包括未触发的。journal.jsonl就是干这个的。

## 七、数据源特有的偏误

### 7.1 yfinance 偏误

| 偏误 | 说明 | 应对 |
|:-----|:-----|:-----|
| 事后修正 | yfinance的数据是事后整理的，和当时终端看到的不同 | 无法完全避免，注意回测不可过度拟合 |
| 分红/拆股调整 | Adj Close算法有bug | 验证多个来源 |
| 缺失交易日 | 某些市场节假日数据可能缺失 | 检查后插值或标记 |
| 停牌日处理 | 停牌日数据为前一日收盘价 | 注意不要误判为"横盘" |
| **限流 (Rate Limit)** | **高频请求被 Yahoo 封 IP** | **Clash 代理切换节点绕过（`clashproxy.py jp`）** |

### 7.2 baostock 偏误

| 偏误 | 说明 |
|:-----|:-----|
| 数据库维护延迟 | baostock的数据可能滞后1-2个交易日 |
| 只有A股 | 只覆盖沪深交易所，不支持期货/期权 |
| 无实时数据 | 历史数据库，不适合短线交易 |

### 7.3 搜索/另类数据偏误

| 偏误 | 说明 |
|:-----|:-----|
| 搜索结果排序偏误 | 前几页结果不代表整体 |
| 新闻情绪偏误 | 坏新闻比好新闻传播更快更广 |
| 信息来源偏误 | 依赖特定来源（如雪球/东财）会强化特定立场 |

## 八、正确的回测设计规范

### 8.1 FengInvest 回测标准协议

```
对于一个"可信"的回测，必须满足以下所有条件：

✅ 信号发生在T-1日收盘时
✅ 成交在T日开盘（开盘价成交）
✅ 手续费按三档分别计算
✅ 信号生成用Unadj Close或Forward Close
✅ 财务数据滞后至少1季度
✅ 包括退市/剔除股票（至少当前可解范围内）
✅ 成分股列表以生效日为基准
✅ 样本外验证（至少回测期后20%的数据）
✅ 三档手续费下都显著
❌ 不允许"当日收盘信号+当日成交"
❌ 不允许"今日最高/最低/收盘价"作为信号
❌ 不允许无滞后期的另类数据
```

### 8.2 处理规范中不确定性的原则

当你不确定一个数据在T日是否可得知时，**默认是不可知的**。

**举证责任倒置**——在回测中，你**必须证明**某个数据在决策时间点是可得的，而不是假定它可得。

## 九、总结：偏误控制优先级

| 优先级 | 偏误 | 影响程度 | 修复难度 | 建议行动 |
|:------|:-----|:--------|:--------|:---------|
| P0 | 价格前视（用当日High/Low/Close） | ⭐⭐⭐⭐⭐ | 低 | 所有因子立即修正 |
| P0 | 幸存者偏差（缺历史成分股） | ⭐⭐⭐⭐⭐ | 高 | US→CN→JP 分批修复 |
| P0 | 退市偏差 | ⭐⭐⭐⭐ | 中高 | 补充退市数据 |
| P1 | 财报数据滞后 | ⭐⭐⭐⭐ | 低 | 回测框架+1季 |
| P1 | 指数调仓偏差 | ⭐⭐⭐ | 中 | 历史成分股重建 |
| P1 | 另类数据滞后 | ⭐⭐⭐ | 低 | 一律+1期 |
| P2 | 复权偏差 | ⭐⭐⭐ | 低 | 信号用Unadj Close |
| P2 | 确认偏误 | ⭐⭐⭐ | 中 | L3碰撞强制反方 |
| P3 | 数据挖掘过拟合 | ⭐⭐ | 高 | 样本外验证 |
| P3 | 选择性报告 | ⭐⭐ | 低 | journal.jsonl强制记录 |

> **一个干净的数据库 ≠ 一个无偏误的回测。**
> 偏误的减少不是靠数据库的多，而是靠对数据"时间属性"的理解。
> 所有偏误的本质都是同一件事：**你（的回测）在数据可见之前就使用了它。**

## 附录A：FengInvest 数据库数据状态声明

### A.1 Close 字段 = 前复权（已确认）

FengInvest 数据库的 `daily_data.close` 字段存储的是 **yfinance auto_adjust=True 的前复权收盘价**，即：
- 已对 **拆股（Stock Split）** 做调整 → 始终保留
- 已对 **分红（Dividend）** 做调整 → 前复权的标准做法
- 调整因子为连乘积 Π[C_exdiv / (C_exdiv + D)]，每项在 (0,1)，所以 **不会为负**

**不会变负的证明：**
- 每次分红的调整因子 = `当日除权收盘 / (当日除权收盘 + 分红)`
- 分子 < 分母，结果恒在 (0,1)，所有因子连乘也在 (0,1)
- 乘以正数的原始价格 → 始终正数
- 实测 MO（累计分红 83392% 的极端案例）：前复权 Close 最小值 $0.0014 > 0

**影响评估：**
| 指标 | 前复权 vs 不复权一致性 | 结论 |
|:-----|:----------------------|:-----|
| 20日均线突破 | 98.15% | 可忽略 |
| 200日均线（年线） | 95.83% | 可忽略 |
| 12月动量因子 | r=0.9998 | 无影响 |
| 60日波动率 | r=0.9999 | 无影响 |

### A.2 指数数据 = 价格指数（不复权）

数据库中的指数（`^GSPC`、`^HSI`、`000300.SS` 等）均为 **价格指数（Price Return Index）**，不包含分红再投资，不需要复权调整。总回报指数（Total Return Index）仅在 US 市场有 `^SP500TR` 可用，HK/CN 暂无可用 yfinance 总回报指数。

### A.3 确认的已知问题

| 问题 | 状态 | 影响 |
|:-----|:-----|:-----|
| 信号生成用了含未来分红调整的价格 | **已确认，影响极低** | 均线/动量/波动率一致率 > 95% |
| 前复权可能变负 | **不会发生** | 数学上不可能，全市场实测未发现 |
| 指数 vs 个股 基准不可比（价格 vs 全收益） | **已确认** | 回测中需注明基准类型 |
| 后复权数据缺失 | **待补充** | US/CN/HK 核心市场补充 |

### A.4 三大市场（US/CN/HK）数据策略

#### 双重数据架构

**股票层面**（个股因子、选股分析）→ 维护四维价格数据：
| 数据类型 | 当前 | 目标 |
|:---------|:-----|:-----|
| 前复权 OHLC（当前 Close） | ✅ 已有 | 维持 |
| 不复权 Close（`unadj_close`） | ✅ 列已建，待回填 | P1 |
