# P层示例 — 组合层怎么用（开源参考示例）

> **定位**：构造型示例（illustrative），不含个人持仓/个人成本/真实交易数据。用于让尚无真实持仓的人看懂「FengInvest 的组合层到底怎么用」。
> **基准来源**：本示例的规则/口径来源自本系统的 [docs/09-portfolio.md](docs/09-portfolio.md)（正交维度 + 集中度 + 资金墙 + 组合检查流程 + 硬约束 + DK 取舍）。
> **读法**：先看 §1 架构 → §2 示例持仓怎么标轴 → §3 集中度怎么算 → §4 置信度怎么映射到仓位 → §5 钱仓滚存 → §6 卖出/复盘/监控怎么串。

---

## §1. 组合层的目标与输入（示例）

- **组合层（P层）的输入**：
  - 个股研究结果（七层走完后的 thesis + redlines + 置信度），来源是 L2a 定性决定的产出。
  - 市场/汇率取数（用于合并口径与集中度算）。实时汇率走 `fengdata.py fx`；缺实时则回退快照并标记 live=false。
  - 资金池信息（哪些钱可以用、用在哪个账户）。

- **组合层的输出（示例）**：
  - 正交三轴分布（market × segment × qualifier）。
  - 各维度集中度与告警。
  - 钱仓滚存（多少在现金/准现金池里、多少可用于新买入）。
  - 购买预算（哪个资金池有余额）。
  - 卖出/复盘/监控记录的串联。

## §2. 正交三轴示例（示例标的的标法）

> 三轴是正交的——市场 / 细分板块 / 现金质性，互不重叠地描述一笔持仓的风险来源与现金属性。

示例用若干示例标的，分别演示怎么标：

| 示例编号 | 示例标的（仅示例名） | market | segment | qualifier | 说明 |
|:---|:---|:---|:---|:---|:---|
| E-1 | 示例：A 类券商软件 | CN_A | 金融.软件交易基础设施 | equity | A 股上市，暴露在中国 A 股市场，细分到金融里的软件交易基础设施 |
| E-2 | 示例：B 类半导体设计 | CN_A | 半导体.AI算力 | equity | 中国 A 股，上细分到 AI算力侧，和存储/代工不同驱动 |
| E-3 | 示例：C 类保险 | CN_A | 保险 | quasi_cash | 中国 A 股，合格作为准现金用（前面 docs/09-portfolio.md 提过低波高息 ETF 等「等机会栖身」类） |
| E-4 | 示例：D 类互联网 | CN_OVS | 互联网 | equity | 中概境外上市，暴露在境外上市的中国互联网风险 |
| E-5 | 示例：E 类医药 | US | 医药 | equity | 美国上市，医药细分 |
| E-6 | 示例：F 类现金资产 | CN_IN | cash | cash | 境内现金池里的真现金 |

要点：
- segment 要细到能区分同行业不同风险驱动（例如半导体里 AI算力 vs 存储 vs 代工是不同的），而不是粗放到 GICS 大类。
- market 家国轴描述暴露在哪，segment 细分轴描述风险驱动，qualifier 描述是否当现金用。
- 词汇表可扩展：买新东西就加新词，轴照样算，不设「XX专属桶」。

## §3. 集中度示例（示例算法）

> 集中度是算出来的，不是写死的。分母是总资产（含资金池），同时也输出该维度占权益的百分比（pct_equity）供参考。

以下示例数值全是构造值，不代表真实持仓：

### 示例 3.1 — 各维度占总资产比例（构造示例）

| 维度 | 占总资产 % | 阈值参考 | 告警 |
|:---|:---|:---|:---|
| market=CN_A | 42% | >28% 黄 / >35% 红 | 示例中 CN_A 市场暴露偏高，触发重审 |
| market=CN_OVS | 8% | >28% 黄 / >35% 红 | 示例中未超 |
| segment=互联网（含中概） | 12% | >20% 黄 / >25% 红 | 示例中未超 |
| 单只示例 A | 18% | >15% 黄 / >20% 红 | 示例中 A 超过黄线但未破 20%，示例中设定为「确定性较高，可暂不卖」 |
| 单只示例 E | 6% | >15% 黄 / >20% 红 | 示例中未超 |
| cash池（真现金+准现金） | 14% | — | 不计入权益集中度 |

### 示例 3.2 — 组合轴交叉的集中度（示例）

- market × segment 组合里最高的比如 `CN_A × 半导体.AI算力` 达到某个构造值（例如 15% 示例），在文档里对应的是「>15% 黄 / >20% 红」。
- 告警是哪块高就冒出来哪块，不事先写死「头号集中是 XX」。

### 示例 3.3 — 单标上限（示例）

- 示例中任何单只都不超过 40% 绝对上限（⛔ 不可突破）。
- 如果某示例标的破了 20% 黄线，理由要写在示例里的「为什么可以破」里——七层走完 + thesis + redlines 齐备，理由落决策日志与组合盘面。

### 示例 3.4 — 超限语义（示例）

- 红/黄灯在示例里也是**警示信号**，触发的是「重新审视 thesis 是否仍成立」，不是自动卖出/禁止买入的硬否决。
- 集中度超标不是卖出理由（只约束买入）；卖出只由六类退出理由触发（见 docs/08-exit.md）。

## §4. 置信度对位示例（L3 碰撞后的映射）

> 七层走完、L3 碰撞过后，输出一个置信度（高/中/低）或确定性档次。P层把这个置信度映射到仓位安排，示例里演示怎么映射。

示例映射（构造示例）：

| 置信度档次（示例） | 对应仓位安排（示例） | 示例说明 |
|:---|:---|:---|
| 高（例：七层完整 + thesis 明确 + redlines 齐备 + 碰撞未发现致命矛盾） | 可以放更大仓位，甚至可临时破 20% 黄线（但仍不能破 40% 绝对上限） | 示例里假设某标的置信度高，放在 18% 的示例 A 中，记录理由 |
| 中（例：证据有一定缺口、结论未完全锁定） | 中等仓位，关注后续证据补全 | 示例中某标的置信度中，放在较小仓位 |
| 低（例：论文主要基于假设、缺少反证覆盖） | 很小试仓或暂不买 | 示例中某标的置信度低，只放极小试仓或不进组合 |

要点：
- 置信度不是凭空拍的，它来自七层与 L3 碰撞的结果。
- 示例里不泄露真实理由的具体表述，仅展示「高/中/低怎样映射到仓位」的结构。

## §5. 钱仓滚存示例（示例账面）

> 钱仓是「现金池」和「准现金」合起来看。浙里有多少能动，多少可以用于新买入，会在 check 里反映。

示例构造账面（构造示例）：

| 示例项目 | 金额（示例） | 备注 |
|:---|:---|:---|
| 真现金池（CN_IN） | 示例 X 元 | 境内可动用现金 |
| 准现金（qualifier=quasi_cash，或 asset_type=cash） | 示例 Y 元 | 例如低波高息/保险财险等当现金用的部分，当机会来时重新分类 |
| 境外/海外可动金额（OVERSEAS 池） | 示例 Z 元 | 用在可买海外标的的钱（注意资金墙约束的是钱出自哪个账户，不是买什么市场） |
| 总钱仓（示例） | X+Y+Z | 不参与权益集中度，只用来描述可买入余额 |
| 钱仓滚存检测（示例） | 在示例里标记是否有钱滞留、是否有放错位置 | 示例里演示滚存检测：钱躺在不该躺的位置是否存在 |

资金墙示例说明：
- 人民币可以买纳斯达克 QDII / 中概 / 港股基金，港币可以买 A 股 ETF，美元可以买中概——资金墙不限制获得市场敞口。
- 约束的是「买什么账户出钱」，而不是「风险暴露在哪」。

## §6. 检查 / 卖出 / 复盘 / 监控怎么串（示例流程）

> 示例里演示这些东西在组合层里怎么串起来。

### 示例 6.1 — 组合检查流程（示例命令串）

```bash
python tools/fengdata.py fx          # 刷新实时汇率（示例里代表取数）
python tools/fengportfolio.py check  # 三轴分布 + 资金池 + 集中度告警 + 买入预算
python tools/fengportfolio.py status # 人类可读盘面
python tools/fengportfolio.py sector # 板块视图
python tools/fengportfolio.py correlate # 持仓相关性
python tools/fengportfolio.py stress # 宏观情景压力测试
```

每次调仓（买入/卖出/现金变动）后必跑 check（示例里也这么写）。

### 示例 6.2 — 新买入前的相关性检查（示例）

- 与现有持仓相关系数 >0.8 → 降仓位（示例）。
- >0.9 → 除非极强分散需求，否则不增（示例）。
- 组合平均相关系数应 <0.6（示例）。

### 示例 6.3 — 卖出闭环在示例里长什么样

- 卖出由六类退出理由触发（见 docs/08-exit.md），不是由集中度超标触发。
- 示例里假设某个示例标的触发卖出，过程是：识别触发源 → 六类理由 → 偏误自查 → 执行卖出闭环。

### 示例 6.4 — 复盘在示例里长什么样

- 复盘走四态假设 + 红线 + 健康度评分 → 写回 reviews → 推进下次回顾日期。
- 示例里可以假设某示例标的复盘之后，得分下跌，推进下次回顾日期靠前。

### 示例 6.5 — 监控在示例里长什么样

- 监控里有 daily / check / review / sell / history / outcome。
- 示例里假设某标的异动后触发 news-pulse 类快速归因，进而决定是否重审 thesis。

## §7. 这个示例里没有的东西（边界重申）

- 没有个人持仓/个人成本/个人仓位决策。
- 没有个股七层中间产物/状态机运行态。
- 没有数据库本体及其伴生物。
- 没有凭据/私人配置。
- 示例数值全是构造值，仅用于演示结构/映射/流程。

---

## §8. 和真实使用的关系

- 示例读完后，真实使用是把真实持仓 JSON 塞进去，跑 `fengportfolio.py check`，看实时告警与钱仓滚存。
- 示例的目的是让人知道「如果我有持仓，组合层会怎么算、怎么告警、怎么串」，而不是替代真实持仓分析。
