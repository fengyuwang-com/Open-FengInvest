# 自主选股机制（Idea Sourcing）—— thesis-first 的标的发现

> **建立**：2026-09-16（创始人立规当日）
> **入口 skill**：`/fengsource`
> **一句话**：不问"哪个筛子能筛出好股票"，先问"什么样的事业值得拥有"，再去找它。

---

## 0. 为什么建这个机制（一次真实的失败复盘）

2026-08-29 我们用**中证红利指数成分**跑了一次批量选股（批次 `cn_dividend-20260829`）：
100 只池 → 规则粗筛 99 → 排名前 50 → **7 硬指标精筛出 24 只幸存者**。看起来这套流水线工作得很好。

2026-09-16 对这 24 只做护城河/周期性分级，结果是：

| 结论 | 数量 | 代表 |
|:---|:---:|:---|
| DROP（纯周期 / 无护城河） | 15+ | 上峰水泥、陕西煤业、中国海油、神火股份、广汇能源、晋控煤业… |
| BORDERLINE（特许经营但有商品敞口） | 1 | 唐山港（岸线特许 × 矿石/煤炭吞吐量） |
| KEEP（可识别护城河 + 收入非大宗价格驱动） | 2 | 皖通高速（收费公路特许）、格力电器（品牌+渠道+自研部件） |

**24 只里 15 只以上是纯周期股。**创始人当天的判断是："筛出来都是周期股，这批大部分不需要考虑了。"

这不是筛选器"没调好"，而是**筛选范式本身错了**。本文档的第 1 节解释为什么这是必然的，第 2 节起给出替代范式。

---

## 1. 根因：screen-first 必然掉进周期陷阱

### 1.1 数学上的必然

红利/价值类筛选器的典型条件是「**高股息 + 低 PE + 高 ROE**」。把这三个条件代入周期股的盈利高点：

| 周期位置 | 盈利 | 股息率 | PE | ROE | 筛子怎么看 |
|:---|:---|:---|:---|:---|:---|
| 景气高点 | 暴利 | **极高**（分红基数大） | **极低**（分母是峰值利润） | **极高** | ✅ 三项全过 |
| 景气低谷 | 亏损 | 0 或停发 | 亏损无意义 | 负 | ❌ 全不过 |

**周期股在景气高点时，长得和"高股息低估值优质股"一模一样。**任何以"当期财务比率"为输入的筛子，都会在周期顶部把一揽子周期股选出来——而且**选得越严格，越偏向周期顶部**，因为那时候各项指标最漂亮。

这不是数据问题、不是阈值问题，是**时序错位**：筛子读的是**某一时刻的快照**，而它想回答的是**跨越周期的问题**。

### 1.2 更深一层：筛子的输入里没有"生意"

这类筛选器的所有条件都是**结果指标**（股息率、PE、ROE、毛利率），没有一个条件在问：

- 它卖的东西，**价格是谁定的**？
- 客户**能不能不用它**？
- 十年后**这个需求还在吗**？
- 赚到的钱**能不能留住**（还是要投回去买设备/买矿）？

**结果指标可以伪装，生意本质很难伪装。**周期股可以在某一年把 ROE 做到 30%，但它永远说不出"为什么客户非我不可"。

### 1.3 结论

> **标的的发现必须从"生意"出发（thesis-first），而不是从"指标"出发（screen-first）。**
> 筛选器不废弃，但它的位置要**后移**——它是**闸门**，不是**入口**。

## 2. 机制总纲

```
        五条发现路径（AI 自主，从生意出发）
   需求锚定 · 产业链瓶颈 · 沿链扩散 · 非共识 · 聪明钱反读
                        │
                        ▼
              闸门 0 — 证据闸（≥3 条带 URL 的客观事实）
                        │
                        ▼
              闸门 1 — 周期闸（创始人 2026-09-16 立规）
                        │
                        ▼
              闸门 2 — 护城河闸（必须命中至少一条且有证据）
                        │
                        ▼
              闸门 3 — 去劣闸（复用 fengscreen 7 硬指标 + 3 豁免）
                        │
                        ▼
      候选卡 → data/config/research_list.json (status: candidate/watching)
                        │
                        ▼
                 排队 → /fenginvest 七层
```

**关键顺序**：`生意 → 护城河 → 周期 → 财务`。
现有流水线是 `财务 → 财务 → 财务 → 生意`（几乎不问生意）。本机制把它倒过来。

## 3. 五条发现路径（AI 自主）

每条路径都要求：**先有线索 → 先查证 → 再立卡**。禁止"想到一个名字就写进候选池"。

### 路径 1｜需求锚定法（从不变的需求倒推）

**输入**：无（从零开始）

**程序化执行器（2026-09-26 起）**：`tools/fengsweep.py` + `data/config/needs_grid.json`，协议说明书 [SWEEP-PROTOCOL.md](./SWEEP-PROTOCOL.md)。把本节需求表展开为 103 个格子 × 5 市场游标，接力扫描一次一格，出候选卡或贫瘠记录，游标永远向前。

**做法**：
1. 列出 **10 年后大概率仍然存在**的底层需求（不是风口，是需求）：吃、穿、住、行、健康、能源、算力、支付、通信、安全、教育、娱乐、养老。
2. 对每个需求问：**谁在满足它？这个位置会不会被替代？**
3. 找那些"需求不变、而供给格局已经稳定"的位置——这是护城河最容易存在的地方。
4. 对每个候选做闸门 0 的证据查证。

**输出**：候选线索清单（未验证）→ 进入闸门流程

**反例警示**：不要从"最近涨得好"的行业倒推需求。那是路径 4（非共识）的反面。

---

### 路径 2｜产业链瓶颈法

**输入**：一个产业链（如 AI 算力 / 电动车 / 电力）

**做法**：复用 ai-berkshire 的 `bottleneck-hunter`（正文已并入本仓：`research/130-external-frameworks/ai-berkshire/skills/bottleneck-hunter.md`）。
1. 画出链条：上游材料 → 中游制造 → 下游应用。
2. 找**卡脖子环节**：谁的交期最长、谁在涨价、谁被下游追着签长单。
3. 瓶颈环节里问：这个瓶颈是**暂时的**（扩产就没了）还是**结构性的**（技术/资源/牌照壁垒）？
   - 暂时瓶颈 = 周期股，会被产能消灭 → DROP
   - 结构性瓶颈 = 可能有护城河 → 进闸门

**输出**：候选线索 + 瓶颈性质判定（暂时/结构性）

---

### 路径 3｜沿链扩散法（从已知标的出发）

**输入**：已研究/已持有的公司（`data/config/research_list.json` + `research/060-companies/`）

**做法**：
1. 取一个已研究透的公司，问四个方向的问题：
   - **上游**：它的核心成本项是谁供的？这个供应商有没有议价权？
   - **下游**：它卖给谁？谁在赚它的下游的钱？
   - **对手**：竞品是哪些？为什么它赢/输？
   - **替代者**：什么东西可能干掉它？
2. 从这四个方向挑出**同样有生意质量**的标的。

**优势**：已有认知可复用，边界清晰，是最省力的一条路。

**输出**：候选线索 + 与已知标的的关系（同链/竞争/替代）

---

### 路径 4｜非共识法

**输入**：无

**做法**：找**被市场归类错**的好生意。三类靶子：
1. **被当成周期股的好生意**：行业被贴了周期标签，但个别公司其实有定价权（毛利率平稳、谷底不亏）。
2. **被当成"老生意"的稳定生意**：没人看，但需求稳定、格局稳定。
3. **被坏消息压住的生意**：坏消息是一次性的还是结构性的？结构性 → 不是机会。

**关键检验**：非共识必须是**你对了、市场错了**，而不是**市场对了、你情绪化**。所以要求：
- 你能说清楚市场共识是什么（要引来源）；
- 你能说清楚你的分歧点在哪；
- 你有市场没看到的事实（要引来源）。

**输出**：候选线索 + 市场共识 + 分歧点 + 支撑事实

---

### 路径 5｜聪明钱反读法

**输入**：公开持仓披露

**做法**：
- 美股：`python tools/fengsec.py ownership <TICKER>` / `13f`（Form 13F 机构持仓、Form 3-5 内部人）
- 公开大师组合、知名长期投资者披露

**铁律**：
> **只允许把披露当作"线索来源"，禁止当作"理由"。**
> 看到某人买了，只能触发"去查这家公司为什么值得买"，**不能**写"因为 XXX 买了所以买"。抄作业是本机制明确禁止的行为（也违反 L0 能力圈：你抄来的仓位超出你的能力圈）。

**输出**：候选线索（须经闸门 0 独立查证）

## 4. 三道闸门

> 闸门的作用是**在投入七层分析之前做排序与标记**：谁先研究、带着什么问题进去。**闸门不能替代七层与创始人的综合判断，不能把任何公司排除出研究范围**（2026-09-20 创始人裁定：投资是综合决定，不许让渡给程序判据；数据/硬筛不许在研究之前拦人）。

### 闸门 0 — 证据闸（硬性，无豁免）

**必须凑齐 ≥3 条带 URL 的客观事实**，分别回答：

| # | 要回答的问题 | 来源要求 |
|:--|:---|:---|
| 1 | **主营与收入结构**：钱从哪来？各业务占比？ | 年报/财报原文、交易所公告 |
| 2 | **竞争格局**：主要对手是谁？它的位置？ | 行业协会、第三方市占率报告、对手财报 |
| 3 | **定价权证据**：提价历史 / 毛利率溢价 / 份额稳定 | 财报 + 第三方 |

**达不到 3 条 → 暂缓进池**（标"证据不足"留档备查，补齐即复活）——**这是暂缓不是否决**：闸门 0 只验证据真实性，不构成对公司的否定（2026-09-20 创始人裁定：任何闸门都无权把公司排除出研究范围）。
**来源 URL 只拿到域名级（如 `pdf.dfcfw.com`）→ 必须标"未能回溯原文"，不得当完整来源用**（这是本机搜索通道的已知退化，见 §8）。

### 闸门 1 — 周期标记闸（2026-09-20 创始人裁定重写）

> **创始人原话（2026-09-20，逐字见 `design/FOUNDER-VOICES.md`）**：
> 「周期性公司如果现在在周期底部是可以研究的。」
> 「硬筛是我的那个标准的一部分，我没有任何一个标准是说只要硬筛就可以把一家公司排除的，这是不存在的。」
>
> **本闸门只许标记与排序，不许排除。**判据命中 = 给候选卡打"周期属性"事实标记，并把"当前周期位置"列为七层第一题。
>
> ※ **历史勘误**：本节旧版引用的「周期性公司和这种没有护城河的公司不要研究」**不是创始人原话**——9/16 原话针对的是中证红利筛出的那 24 只（"这二十几只大部分都是周期股，都不需要考虑了"），是转述加工后被放大成了机制条款。原话全文见 FOUNDER-VOICES 2026-09-16 节。

**判据（可操作，任一命中即高度疑似纯周期）**：

| 判据 | 怎么测 | 周期信号 |
|:---|:---|:---|
| **A. 价格接受者** | 售价主要由公开商品/运价/利率市场决定？ | 是 → 周期 |
| **B. 毛利率摆动** | 近 10 年毛利率的极差与标准差 | 极差 > 15pp 且与商品价格同向 → 强周期 |
| **C. 谷底检验** | 行业最差年份它赚钱吗？ROE 正吗？ | 谷底亏损/负 ROE → 周期 |
| **D. 提价历史** | 成本没涨时提过价并保住份额吗？ | 无提价记录 → 无定价权 |

**判据 B/C 可程序化**：本地库 `data/market_data.db` 的 `cn_financials` + `daily_data` 可算毛利率序列与谷底年份 ROE。
（工具化待办：`tools/fengsource.py` 的 gate 子命令，见 §9。）

**标记规则**：命中条数 = 周期强度标记（0 条 = 非周期；1 条 = 疑似周期；≥2 条 = 强周期标记）。**无论命中多少，一律进池参与排序**——是否研究、何时研究由七层分析与创始人综合判断定。
**七层第一题（强周期标记者必答）**：当前处于周期什么位置？——**在底部/底部区域 → 正常研究**（创始人：底部的周期性公司可以研究）；在景气高位 → 挂起等回落。"周期之上有没有结构"（存储三巨头 HBM 寡头型）仍是七层核心论证，但它决定的是结论，不是能不能进门。东方海外（0316.HK）、中国海外发展（0688.HK）已按本裁定恢复进池（2026-09-20）。

### 闸门 2 — 护城河闸

**必须命中至少一条，且每条都要有证据（不许只写"品牌优势"这种空话）**：

| 护城河类型 | 可验证的证据形态 |
|:---|:---|
| 品牌溢价 | 同规格产品价格显著高于同业，且**份额没有因此流失** |
| 转换成本 | 客户换掉它的实际代价（迁移期/数据/认证/停机成本） |
| 网络效应 | 用户/供给越多，单边价值越高的机制 + 数据佐证 |
| 规模成本优势 | 单位成本显著低于同业，且**不是靠补贴/一次性因素** |
| 牌照/特许 | 政府授予的排他权利（有期限的要写明剩余年限） |
| 技术代差 | 领先至少一个可验证的世代，且有第三方佐证 |

**明确不算护城河的**（本次分级中反复出现的伪护城河）：
- "渠道规模大"（渠道大 ≠ 客户非你不可）
- "自述市占率第一"（无第三方佐证 = 无来源）
- "成本领先"（若成本优势来自资源禀赋/规模而产品同质，则只是**成本壁垒**，不排他 → 归入 BORDERLINE，交七层/创始人综合判断）
- "行业第一但份额只有 5%"（行业极度分散本身说明无壁垒）

### 闸门 3 — 去劣闸

**通过闸门 0/1/2 后**才跑 `fengscreen` 的 **7 硬指标 + 3 豁免**（宁可漏网不可误杀）。
作用：财务造假/治理问题/资本纪律差的一票否决。详见 `.agents/skills/fengscreen/SKILL.md`。

## 5. 候选卡（Idea Card）格式

每个进池的候选写一张卡，**字段固定，缺项留空不许编**：

```markdown
# <TICKER> <中文名> — 候选卡

- **发现路径**：路径 N（需求锚定/瓶颈/沿链/非共识/聪明钱反读）
- **发现日期**：YYYY-MM-DD
- **谁发现的**：<会话标识>
- **一句话生意**：它卖什么、谁买单、为什么选它
- **收入结构**：<占比表>（来源：<URL>）
- **定价权**：价格制定者 / 价格接受者（依据 + 来源）
- **护城河**：类型 + 证据 + 来源（≥1 条）
- **周期判据**：A/B/C/D 逐条结论
- **同行对比**：<对手> vs 本标的（关键指标）
- **市场共识 vs 我的分歧**：（仅路径 4 必填）
- **最可能被推翻的点**：<自己写出最弱的假设>
- **闸门结论**：PASS / BORDERLINE / 标记（周期属性·证据缺口）（+ 理由）——自 2026-09-20 起无 DROP 选项，闸门不排除公司
- **下一步**：排队七层 / 观察 / 归档
```

**「最可能被推翻的点」是必填项**——这是本机制的自纠错装置。本次 24 只分级里，两个专家子代理各自独立给出了"最没底气的 3 只"，其中永兴材料、中谷物流两只的 DROP 都建立在**规则解释**而非**事实**上，正是靠这一项暴露出来的。

## 6. 反偏见清单（沿用并强化）

筛选/发现过程中必须警惕 5 类偏见（来自 ai-berkshire `industry-funnel`）：

| 偏见 | 表现 | 对策 |
|:---|:---|:---|
| **龙头偏好** | 资料多 ≠ 更好，大公司天然被搜到 | 按硬指标打分，不按知名度 |
| **英文偏好** | A/H/韩/日股资料少就被略过 | 中英日韩**都要搜**（韩股必须用韩文搜） |
| **故事偏好** | 把"AI 故事占比"当"AI 收入占比" | 只认财报科目里的收入 |
| **当下偏好** | 当前财务好 ≠ 长期好 | 强制看 10 年序列，不看单年 |
| **上市偏好** | 只看得懂已上市的 | 关注 IPO 候选（延后处理） |

**本机制新增第 6 条**：

| **筛子偏好** | 习惯性回到"跑个筛子看看" | 本机制入口禁止跑筛子（见 §1） |

**偏见影响结论时必须在卡片里注明。**

**两个程序件（机制的可执行半边）**：

| 工具 | 职责 | 关键设计 |
|:---|:---|:---|
| `tools/fengsource.py` | 闸门层：`gate`（闸门 1 判据 B/C）、`ledger`（台账读写）、`check`（去重自检） | 算不出来一律 **ABSTAIN 出声**，不用默认值/0/中性值冒充；DB 只读打开；输出逐点标注口径（哪个字段原值、哪个是推算） |
| `tools/fengsweep.py` | 零输入扫描层（2026-09-26 建）：`grid`/`status`/`next`/`record`/`cursor` | 格子表 × 游标推进；排序器只定「先看谁」（不筛人）；barren 必须写明原因；台账 sweep.jsonl 状态即台账（append-only）。协议见 SWEEP-PROTOCOL.md |
| `tools/fengqueue.py` | 调度层：队列四态 + 并发上限 + 派单台账 | **队列数据驱动**——读 `research_list.json` 的 `researching/candidate`，不再硬编码名单；另算「队列之外仍在跑」的标的，避免并发度漏算导致重复派单 |

> 只有这两份是调度/闸门的唯一入口。历史上曾并存过第二份接力实现
> （`Temp/research_relay.py`），已退休——**两个调度器各写一本台账会让并发度算错、
> 进而重复派单**，这是本机制明确要避免的竞态。

**上游联动**：
- 通过闸门的标的 → 写 `data/config/research_list.json`，`status: candidate`（只写"研究谁"，**禁止写仓位/成本等交易字段**）
- 排队执行 → `/fenginvest <TICKER>`；调度由 `tools/fengqueue.py` + 每 20 分钟定时任务接管
- 已开户的持仓 → `holdings/`（本机制不碰持仓）

**淘汰档案的价值**：本次 24 只的 DROP 理由全部留档，将来任何筛子/任何人再问起这 24 只，直接查档案，不重复劳动。
