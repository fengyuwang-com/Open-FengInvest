# 零输入发现协议（Zero-Input Sweep）—— 路径 1「需求锚定」的程序化落地

> **建立**：2026-09-26（创始人批准「这个想法好 就这么办」当日，逐字存档见 `design/FOUNDER-VOICES.md`）
> **执行入口**：`tools/fengsweep.py`
> **格子表**：`data/config/needs_grid.json`
> **一句话**：什么都不说时，prompt 换成**一张需求表 + 一个游标 + 一套不变规则**——AI 从「等指挥」变成「按地图扫雷」。

---

## 0. 诞生缘起

自主选股机制（本目录 README）建成后的两次实战（09-16 存储三巨头、09-20 沿链扩散 + 恒指宇宙）都有一个隐藏的起点：**创始人的指点**。五条路径里标着「输入：无」的路径 1（需求锚定）与路径 4（非共识），一次都没真正跑过。

2026-09-26 创始人问：「什么都不说怎么找好股票？」——本协议是答案：

> 零输入 ≠ 没有输入，而是**把起点从「变量」换成「常数」**：
> ①需求常数（一张写死的十年需求表）②数据常数（已建成的全市场本地库）
> ③规则常数（三道闸 + 反偏见清单 + 只许排序不许排除）。
> 变量只剩一个：**游标走到哪了**。

## 1. 扫描范式

```
   需求格子表 data/config/needs_grid.json（103 格 × 5 市场游标）
        │  tools/fengsweep.py next  ←─ 每 20 分钟接力领一格
        ▼
   ① 生意先行：先答格子里的生意问句（谁在满足/供给格局稳吗）
        │
        ▼
   ② 排序器定「先看谁」（fengsweep DB 排序，仅排序 ≠ 准入）
        │
        ▼
   ③ 闸门 0 — 证据闸（≥3 条带 URL 客观事实）          ← 同 /fengsource
        ▼
   ④ 闸门 1 — 周期标记闸（fengsource gate，只标记不排除）← 同 /fengsource
        ▼
   ⑤ 闸门 2 — 护城河闸（≥1 条带证据）                  ← 同 /fengsource
        ▼
   候选卡 pool/<TICKER>.md → research_list.json → fengqueue 排队七层
        │
        └─ 什么都没找到 → barren 贫瘠记录（必须写明为什么贫瘠）
```

**每格必留痕**：candidates（出了候选卡）或 barren（贫瘠）。跳过 = 违规。
贫瘠记录与候选卡同为资产——「我们查过这个格子、为什么贫瘠」，下次不重挖。

---

## 2. 为什么是游标而不是 AI 自由探索

AI 自由探索有三个引力（机制 README §6 反偏见清单的三条）：
**只搜得到龙头**（资料多≠好）、**只搜英文**（韩日中小盘全漏）、**忍不住跑筛子**（筛子偏好）。

游标扫描的价值是**确定性覆盖**：格子顺序固定、市场轮转固定、每格产出留痕，
任何一轮接力都可复现、可审计。覆盖率是硬指标（fengsweep status 一目了然），
命中率不是指标（零输入扫描是**召回机制**，精度交给后面的闸门→七层→创始人综合判断）。

## 3. fengsweep.py 使用

```bash
python tools/fengsweep.py grid                # 格子表体检（ID 唯一/字段齐/status 合法）
python tools/fengsweep.py status              # 游标现状 + 覆盖率（按市场分布）
python tools/fengsweep.py next                # 本轮该扫的格子（含生意问句 + 完整流程提示）
python tools/fengsweep.py next --market CN    # 只在 A 股内推进
python tools/fengsweep.py record --cell needs-001 --market CN \
    --outcome candidates --tickers 601298.SH --note "闸门 0/1/2 通过 2 只"
python tools/fengsweep.py record --cell needs-006 --market CN \
    --outcome barren --note "种业 A 股仅 X 只且均无 10 年序列，闸门 0 证据不足，留观察"
python tools/fengsweep.py cursor --set needs-030 --market HK --note "该格与 1997.HK 重复，校正"
```

**台账**：`research/120-idea-sourcing/sweep.jsonl`（append-only）。
**状态即台账**：无独立状态文件，台账顺序重放 = 当前游标。坏行保留原样不吞错。

## 4. 铁律（违反任何一条 = 本轮无效）

1. **排序器不是筛子**。fengsweep 的 top-N 只是「先看谁」，被排序否掉 ≠ 排除出研究
   （2026-09-20 创始人裁定：闸门只许排序/标记，不许排除任何公司）。
2. **barren 必须写明原因**。静默跳格 = 违规；"不确定"也是一种原因。
3. **ABSTAIN 出声**。数据缺口如实写（哪个市场、缺什么源），不许用默认值冒充。
4. **闸门 0 证据必须带 URL**，域名级 URL 只能标「未能回溯原文」。
5. **非英语市场用当地语言搜**（韩语/日语，见 RELAY-PROMPT 第二节）。
6. **出卡后登记 research_list.json 只写「研究谁」**，禁止写仓位/成本等交易字段。

## 5. 局限（诚实声明，随进展更新）

1. **覆盖率的分母陷阱**：格次按当前格子表算；扩格子 = 分母变大，覆盖率回落是正常现象。
2. **CN/HK/US 三市场全自动**（申万/fundamentals 行业成员 + cn_financials/global_financials 序列）；
   **KR/JP 仍 ABSTAIN**（无多年财务序列，走 AI 常识名单 + 当地语言搜索）。
3. **HK/US 行业标注覆盖有限**（HK 81 家 / US 501 家有 fundamentals 行业标注，其余标的
   财务序列已回填但无行业归属）——命中 <3 家时 ABSTAIN 走 AI 常识名单，不降级全池乱排；
   扩大覆盖需回填更多行业标注。
4. **美股财年口径**：财年非自然年的公司（苹果 9 月底等）按报告期原样入账标注。
5. **吞吐量**：HK/US 全市场财务序列回填约 20-30 分钟/市场（fengexpand_fin_global --resume
   断点续传）；行业标注回填是后续增量。
6. **格子表是常数**：几年才改一次；发现缺格子/格子错 → 改表并在 note 里留痕，不重排 ID。

## 6. 排序器三修记录（2026-09-26，创始人挑战「你确定都能找到吗」后）

| # | 症状 | 根因 | 修法 |
|:--|:--|:--|:--|
| 1 | 3 年新股（嘉华股份等）排到海天（10 年 11.7pp）之上 | 上市短 → 没经历周期 → 极差天生小，「数据短」被误当「毛利稳」 | 年度毛利率点 <5 不参排（MIN_RANK_YEARS=5），短历史另列提示走 AI 名单 |
| 2 | 华文食品/劲仔食品重复占位 | 同一公司新旧证券名两行 | GROUP BY stkcd 取最新证券名去重 |
| 3 | **伊利股份被漏掉**（乳品格子前排全是种业/畜牧） | 纯关键词检索的结构性盲区：伊利行业标注=「食品制造业」、名字无「乳/奶」字 | 主通道改申万二级行业成分（akshare index_component_sw，30 天本地缓存），关键词降为兜底；98 格配 sw_codes |

**结论：五轮修复后排序器的已知偏差已全部消除；残余风险见 §5。**
排序哲学定案（双梯队 + 残差稳度）：
- **双梯队出榜**：稳健梯队（窗口内从未亏损）+ 深周期梯队（曾亏损、带周期标记出场）——「周期性公司在周期底部可以研究」（创始人 09-20），深周期公司必须能进入视野（top5 = 稳健 3 + 深周期 2）
- **稳度 = 趋势残差标准差**：极差把「单调改善」（如 NVDA 毛利率 58%→75%）误判为不稳；残差 std 只罚震荡不罚趋势
- 同一科学键：谷底年盈利✓ > 数据年限深 > 残差稳度小

## 7. 批量模式（batch，2026-09-26 创始人授权）

```bash
python tools/fengsweep.py batch --market CN --top 3   # 全部格子批量排序，产全行业先看名单
```

产出 `reports/sweep-<日期>-CN.md + .json`：方法节（成员源/排序键/周期闸口径/数据源）+ 分行业表 + ABSTAIN 逐格留痕 + 口径冻结声明。周期标记复用 `fengsource gate` 判据 B/C（同窗口同阈值，不新增自由度）。

**边界**：batch 只是把单格排序器跑遍全表，不新增任何筛选自由度；产出仍是「先看谁」，闸门 0/1/2 与七层仍在前方。报告数字生成即冻结，闸门取证时必须回库对拍（fengcheck 抽数规矩）。

## 8. 与现有机制的关系

| 组件 | 关系 |
|:--|:--|
| `/fengsource` 五路径 | 本协议是路径 1 的程序化执行器；闸门完全复用（同一套三闸） |
| `fengqueue.py` | 出卡登记后排队七层，调度不变 |
| `fengbatch` | 仍降级为给定名单的执行器；本协议**不**给它增加入口地位 |
| `data/expansion` 数据扩张 | 本协议是数据库的下游消费者；排序器质量随 DB 财务覆盖提升而提升 |
