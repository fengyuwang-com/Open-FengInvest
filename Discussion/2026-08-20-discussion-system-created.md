# 讨论系统本身：对抗式讨论是核心资产，需要一个专门的家

> 状态：定稿
> 日期：2026-08-20
> 来源：用户与 AI 就「建一个讨论系统」的本轮对话

## 议题

为什么要为"讨论"单独建一套系统（`Discussion/` + `/fenginvestdiscuss`），而不是继续散落在 docs/10-discussion.md、FENGMEM.md、research/ 里？

## 立场（系统所有者）

1. Discussion（尤其是**对抗式讨论**）在我投资系统里的重要性"不言而喻"——它就是"我跟 AI 的对话本身"，是这套系统区别于其他投研框架的核心资产之一。
2. 真正的需求不是"更多工具"，而是**一场对抗能被记住**。现在这些观点交锋散在 docs/10-discussion.md、FENGMEM.md、research/110-*/、knowledge/ 各处，聊完就找不到——要一个专门安放它们的家。
3. 要**简单**：讨论就是讨论，就是"我跟 AI 的话"。不加状态机、不加 regress 那套重协议，只需引导对话 + 落档。
4. 边界：个股/行业讨论放个股研究（那是另一套已存在的 /fenginvest 系统）；这里只做纯观点/方法论/框架的交锋与结论落档，不产出买卖动作。
5. AI 的对抗是**方法性**而非情绪性——不吼我、不用讨好我，就用我已在用的这套方法（不讨好、完整记反方、结论可推翻、改动留痕）跟我平等辩论。

## 支持证据

- 现有 `docs/10-discussion.md` 已是辩论档案，模板"立场→支持证据→反方→结论→系统改动"、规则"不讨好、反方必须完整、结论可推翻、改哲学前先辩论"——这已是本系统的宪法，只是没被当作独立子系统。
- 今天一整天的对抗（ai-berkshire 三条、小米 WAIT、r 折现率、大师配音）全是"立场 vs 反方"交锋后落定，正是对讨论价值的实证。
- `/fenginvest` 七层框架里 `L3 碰撞 = 反方检查（4问强制）` 已是现成的对抗流程，可被 /fenginvestdiscuss 复用其精神。

## 反方（最强反对论点）

1. **多一个文件夹/多一个 skill 也是复杂度**：若只是把 10-discussion.md 挪个位置，没有增量价值；讨论记录本就能留在 docs/ 里。
2. **拆条会增加维护成本**：一条一个文件 vs 一个单档，索引、命名、迁移都要花精力，可能得不偿失。
3. **对抗若被"仪式化"反而失真**：若每次讨论都套模板、走流程，可能把真实的对抗磨成形式，违背初衷。

## 结论

- **对抗式讨论值得拥有专门的家**——价值不在于"更多机制"，而在于"交锋不散落、结论可回溯、反方恒在场"。
- 系统做到**最简**：一个根目录 `Discussion/`（一条讨论一个文件 + README 索引）+ 一个轻量 skill `/fenginvestdiscuss`（引导「立场→反方→结论」对话 + 落档）。不建状态机、不加 python 工具。
- 边界写死：不做个股/行业分析、不碰状态机/持仓/日志，只产出观点结论。
- 存量（docs/10-discussion.md 8 条）逐条拆成独立文件迁入，原档留指针，可回退。
- 本目录私有；公开 Open-FengInvest 需单独脱敏。
