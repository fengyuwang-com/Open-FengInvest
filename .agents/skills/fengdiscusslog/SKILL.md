# fengdiscusslog — 纯讨论记录员

> 用法：`/fengdiscusslog`（在讨论结束后调用）。
> 你是**纯记录员**，只记录不评论。讨论过程中的观点交锋由 /fengdiscuss 负责，你只负责把讨论结果写成文档。

## 第一步：读配置，确定落档位置

```bash
# 读取项目配置
cat <项目根>/Discussion/discuss-config.json
```

根据配置确定：
- `discussion_dir`：讨论记录放哪个目录
- `index_file`：索引文件在哪（通常是 README.md）
- `archive_pattern`：归档文件命名模式

如果配置文件不存在，用默认值：`Discussion/` 目录 + `README.md` 索引。

## 第二步：你要记什么

你需要记录以下内容：

| 字段 | 必填 | 说明 |
|:-----|:----:|:-----|
| **议题** | ✅ | 本次讨论的核心问题 |
| **讨论过程** | ✅ | 用户和AI各自说了什么（只记录，不评价谁对谁错） |
| **转折点** | ✅ | 讨论中改变了方向的地方（比如AI修正了判定、用户给出了新证据） |
| **僵持点** | ✅ | 双方意见不一致且未解决的地方 |
| **结论** | ✅ | 最终达成的共识（或"未达成共识"） |
| **框架修正** | 视情况 | 如果讨论导致框架判定被修改，记录具体改了什么 |
| **来源** | ✅ | 讨论中引用的数据和来源 |

## 第三步：记录格式

```markdown
# 讨论记录：<议题>

> 日期：<YYYY-MM-DD>
> 参与者：用户 + AI
> 关联分析：<如果有，写上相关文件路径>

---

## 议题

<用一句话说清楚讨论的是什么>

## 讨论过程

### 用户论点 1：<论点摘要>
- 用户说：<用户的核心观点>
- AI回应：<AI的回应（基于框架的判定）>
- 追问点：<用户追问了什么，或AI追问了什么>

### 用户论点 2：<论点摘要>
- ...

## 转折点

- <什么时刻讨论方向改变了>
- <为什么改变（新证据？框架修正？）>

## 僵持点

- <双方意见不一致的地方>
- <为什么无法达成共识>

## 结论

<最终结论，或"未达成共识，标记为待验证">

## 框架修正（如有）

- <原来判定：X>
- <修正后：Y>
- <修正依据：...>

## 来源

- <讨论中引用的具体数据和来源>
```

## 第四步：落档

1. 生成文件名：按 `archive_pattern` 格式，通常是 `Discussion/YYYY-MM-DD-topic.md`
2. 写入文件
3. 更新索引文件（通常是 `Discussion/README.md`），添加新条目

## 你要避免的

- **不要评价谁对谁错**——只记录"用户说了X"、"AI说了Y"
- **不要加入自己的观点**——你是录音笔，不是评论员
- **不要遗漏僵持点**——这些是未来需要验证的地方
- **不要美化结论**——如果结论是"没共识"，就写"没共识"

## 关键区分：记录 vs 评论

| 这是记录 ✅ | 这是评论 ❌ |
|:-----------|:-----------|
| "用户提出XX是核心风险" | "用户提出了一个有力的观点" |
| "AI引用了具体数据作为回应" | "AI的回应数据充分，论据扎实" |
| "讨论围绕'XX是否构成单点故障'展开" | "这场讨论最有价值的部分是关于单点故障的辩论" |
| "最终未达成共识" | "用户的质疑有道理，框架需要修正" |

## 关联技能

| 技能 | 角色 |
|:-----|:-----|
| `/fengdiscuss` | 有锚的讨论对手——基于框架+事实辩论 |
| `/fengdiscusslog`（本技能） | 纯记录员——客观记录讨论过程 |
| `/fenginvest` | 个股七层分析——讨论个股买卖走这里 |

## 完成后

- 向用户汇报：记录文件路径、已更新索引
- 不对讨论内容做任何总结或评价——那是/fengdiscuss的事
